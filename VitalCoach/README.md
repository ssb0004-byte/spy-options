# VitalCoach (Phase 1)

A native iPhone app for adults that brings together body composition, vitals, medication and supplement logging, and daily check-ins. Phase 2 adds an AI coach on top.

**Status:** Phase 1 foundation. Educational and wellness use only; not a medical device.

## Repository layout

```
VitalCoach/
├── VitalCoach.xcodeproj      generated by XcodeGen from project.yml — open this in Xcode
├── project.yml               project definition (targets, capabilities, Info.plist)
├── App/                      SwiftUI app: AppModel, services (SwiftData, HealthKit, notifications), feature views
├── AppTests/                 SwiftData store tests (run with ⌘U)
├── Packages/VitalCore/       pure-Swift domain logic + Supabase client, 86 tests, Swift 6 mode
├── supabase/
│   ├── migrations/           Postgres schema, RLS, triggers
│   ├── functions/            delete-account Edge Function
│   └── tests/                RLS, behaviour and schema round-trip tests (run.sh)
├── Config/                   App.xcconfig + Secrets.example.xcconfig (copy to Secrets.xcconfig)
├── scripts/                  swift-in-docker.sh (run core tests without a Mac)
└── docs/                     ARCHITECTURE · SETUP · TESTFLIGHT · PHASE1_ACCEPTANCE · PRIVACY_AND_DATA · COSTS · RELEASE_READINESS · DEV_CHECKLIST
```

## Quick start

**No Mac?** Follow [docs/TESTFLIGHT.md](docs/TESTFLIGHT.md): GitHub builds and signs the app and delivers it to your iPhone through TestFlight.

**With a Mac:**
1. Open `VitalCoach.xcodeproj` in Xcode 16+, pick an iPhone simulator, press ▶︎.
2. Choose **Try on this iPhone only** to explore without a backend.
3. To enable Sign in with Apple and cloud backup, follow [docs/SETUP.md](docs/SETUP.md).

## Tests

| What | Command | Runs on |
|---|---|---|
| Core logic (86 tests) | `swift test` in `Packages/VitalCore`, or `scripts/swift-in-docker.sh test` | macOS, Linux |
| Database: RLS, triggers, cascade, schema round-trip | `supabase/tests/run.sh` | Linux/macOS with Postgres + Docker |
| App + core | ⌘U in Xcode | macOS |

CI (`.github/workflows/vitalcoach.yml`) runs all three on every push that touches `VitalCoach/`.

## Configuration

`Config/Secrets.xcconfig` (git-ignored) holds your Team ID, bundle ID, Supabase host and anon key. The anon key is public by design; data is protected by Row Level Security. **Secret keys (Supabase service role, OpenAI) must never be put in the app or committed to Git**; they belong only in Supabase server-side secrets.
